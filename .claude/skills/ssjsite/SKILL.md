# ssjsite — 애플 다크 몰입형 디자인 시스템

특정 아카이브 사이트에서 검증된 디자인 언어를, 내용이 전혀 다른 새 사이트에
그대로 또는 살짝 변주해서 입히기 위한 스킬이다. 색·폰트·여백·모션의 조합이
"세련되고 차분한 프리미엄 다크"라는 인상을 만든다. 그 인상을 재현하는 것이 목표다.

## 이 디자인의 정체성 (한 문장씩)

- **배경은 순수 블랙(#000)**. 회색이 아니라 진짜 검정. 그 위에 카드가 뜬다.
- **표면은 iOS 시스템 그레이 계단**: surf #1c1c1e → tint #2c2c2e → tint2 #3a3a3c.
  깊이를 색이 아니라 밝기 단계로 표현한다.
- **폰트는 Pretendard Variable**. 한글 웹폰트의 기준점. 제목은 자간을 -0.028em로
  바짝 조이고 두께를 명시(wght 600~650)해 애플 헤드라인 느낌을 낸다.
- **텍스트는 흰색→회색 4단계**: ink(제목) → body(본문) → mut(보조) → faint(흐림).
  절대 순백 다음에 바로 진회색으로 점프하지 않는다. 항상 계단을 밟는다.
- **액센트는 iOS 블루(#0a84ff)**, 포인트는 골드(#ffd60a). 시맨틱은
  지시=레드·성공=그린·강조=골드로 고정.
- **모션은 절제**: 스크롤 진입 페이드업, 제목 라인마스크, 숫자 카운트업 정도.
  화려한 트랜지션 대신 "차분히 나타나는" 리듬. 전부 prefers-reduced-motion으로 꺼진다.
- **여백은 넉넉**: 섹션마다 py-24, 콘텐츠는 max-w-2xl~4xl로 가운데 묶기.
  빽빽함이 아니라 숨 쉴 공간이 프리미엄 인상을 만든다.
- **한글 가독성**: `word-break: keep-all`로 단어 단위 줄바꿈. 이거 하나로 한글
  레이아웃의 완성도가 크게 갈린다.

## 적용 워크플로우

새 사이트에 이 디자인을 입힐 때 다음 순서로 진행한다.

1. **토큰을 먼저 깐다.** `references/design-tokens.css`를 프로젝트에 복사한다.
   - Tailwind v4 프로젝트면 파일 상단 `@theme` 블록을 globals.css에 붙인다.
   - 순수 HTML이면 `:root` 블록 + 유틸리티 클래스를 그대로 쓴다.
   두 경우 모두 파일 하단의 컴포넌트 클래스(.panel/.chip/.h-judge…)와 모션 CSS가 딸려온다.

2. **Pretendard를 로드한다.** `<head>`에:
   ```html
   <link rel="preconnect" href="https://cdn.jsdelivr.net" crossorigin>
   <link rel="stylesheet"
     href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
   ```

3. **레이아웃 뼈대를 세운다.** 프로스티드 고정 헤더 → 풀블리드 히어로(라인마스크
   제목 + 라디얼 비네트) → overline-label/h-judge로 시작하는 섹션 스택 → 푸터.
   구조와 코드는 `references/motion-and-patterns.md` 6번 참고.

4. **모션을 붙인다.** Reveal(스크롤 페이드업)을 섹션 제목·카드에 두르는 것만으로도
   80%는 완성된다. 필요하면 CountUp(통계), ScrollProgress(상단 바), RotatingWord/
   타자기(히어로 강조), 패럴랙스 배경 사진을 더한다. 코드는 같은 파일 1~5번.

5. **콘텐츠를 이 언어로 번역한다.** 원래 사이트가 무엇을 다루든:
   - 목록/상세는 `.panel` 카드로.
   - 상태·분류는 시맨틱 `.chip`으로.
   - 긴 내용은 네이티브 `<details>` 아코디언으로 접는다.
   - 통계는 큰 숫자(CountUp) + 작은 라벨(mut) 조합으로.

6. **접근성·반응형 확인.** 모든 모션에 reduced-motion 가드가 있는지, 모바일에서
   히어로 높이(100svh)와 터치 타깃이 괜찮은지, 대비가 충분한지 본다.

## 베리에이션 가이드 — 어디까지 바꾸고 어디를 지킬까

**바꿔도 되는 것 (브랜드에 맞게):**
- **액센트 색**: `--color-accent-*` 3개만 바꾸면 전체 인상이 그 색으로 이동한다.
  블루 대신 퍼플(#bf5af2)·틸(#40c8e0)·핑크(#ff375f) 등 iOS 시스템 컬러 계열을
  쓰면 톤이 유지된다. 채도 높은 원색은 피한다(다크 배경에서 눈이 아프다).
- **골드 포인트**: 필요 없으면 빼도 된다. 프리미엄·공공·금융 느낌엔 남긴다.
- **폰트 스케일**: 콘텐츠 밀도에 따라 본문 15~16px 기준으로 오르내린다.
- **히어로 배경**: 파티클/3D 캔버스, 저투명 사진 패럴랙스, 단색 비네트 중 택1.

**반드시 지켜야 하는 것 (안 지키면 톤이 무너진다):**
- 순수 블랙 배경 + 밝기 단계 표면. 표면에 색을 넣지 않는다.
- 텍스트 4단계 회색 위계. 중간 단계를 건너뛰지 않는다.
- Pretendard + 제목 자간 조이기 + keep-all.
- 넉넉한 여백과 가운데 묶기. 폭을 꽉 채우지 않는다.
- 절제된 모션 + reduced-motion 가드. 요소마다 다른 화려한 효과를 남발하지 않는다.

## 흔한 실수 (피할 것)

- 배경을 #111이나 다크그레이로 → 블랙의 깊이가 사라진다. #000을 쓴다.
- 카드 배경에 파란/보라 틴트 → surf는 무채색 그레이여야 한다. 색은 액센트로만.
- 제목에 기본 자간 → 반드시 letter-spacing을 조여야 애플 느낌이 난다.
- 모션을 섹션마다 다르게 → Reveal 하나로 통일하는 게 오히려 고급스럽다.
- 콘텐츠를 폭 끝까지 → max-w로 묶고 좌우 여백을 살린다.
